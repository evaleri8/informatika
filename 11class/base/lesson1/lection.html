Цель урока: объяснить назначение компьютерных сетей, принципы их построения и работу основных сетевых устройств; раскрыть роль протоколов, IP-адресов и системы доменных имён DNS.

1. Компьютерная сеть и её назначение

Компьютерная сеть — совокупность компьютеров и других устройств, соединённых каналами связи для передачи данных и совместного использования ресурсов.

В сети можно обмениваться файлами, обращаться к общему принтеру, использовать удалённые серверы и совместно работать с документами.

Локальная сеть (LAN)

Объединяет устройства в пределах кабинета, здания или небольшой территории.

Глобальная сеть (WAN)

Объединяет сети и устройства на больших расстояниях.

Интернет

Глобальная система взаимосвязанных сетей, использующих семейство протоколов TCP/IP.

2. Принципы построения компьютерных сетей

Устройства соединяются физическими каналами (например, кабелем) или беспроводной связью (Wi‑Fi). Топология сети описывает схему соединения узлов. В типичной школьной локальной сети используется структура типа «звезда»: компьютеры подключаются к центральному сетевому устройству.

3. Аппаратные компоненты сети

КомпонентНазначение
Сетевой адаптерОбеспечивает подключение устройства к сети (Ethernet или Wi‑Fi).
Кабель / радиоканалСреда, по которой передаются сетевые сигналы.
Коммутатор (switch)Соединяет устройства локальной сети и пересылает кадры на нужные порты на основе MAC-адресов.
Маршрутизатор (router)Соединяет разные IP-сети и выбирает путь передачи пакетов по IP-адресам.
Точка доступа Wi‑FiПодключает беспроводные устройства к локальной сети.
Пример: школьный компьютер передаёт файл другому компьютеру в той же LAN через коммутатор. При обращении к ресурсу вне локальной сети пакеты обычно направляются через маршрутизатор.

В домашних устройствах функции маршрутизатора, коммутатора и точки доступа часто объединены в одном корпусе.

4. Сетевые протоколы и передача данных

Сетевой протокол — набор правил, определяющих формат сообщений и порядок взаимодействия устройств. Для обмена данными в Интернете используются взаимосвязанные протоколы, которые часто называют стеком TCP/IP.

ПротоколОсновная функция
IPАдресация устройств и доставка пакетов между сетями по выбранному маршруту.
TCPНадёжная передача упорядоченного потока данных с контролем доставки.
HTTP / HTTPSОбмен веб-запросами и ответами; HTTPS защищает соединение шифрованием.
DNSПолучение сетевых сведений по доменным именам, в том числе поиск IP-адреса.

При передаче данные могут разбиваться на отдельные пакеты. Маршрутизаторы пересылают их между сетями; принимающая сторона обрабатывает полученные данные.

5. Адресация в Интернете

IP-адрес — числовой адрес сетевого интерфейса в IP-сети. Он необходим для адресации и маршрутизации пакетов.

IPv4

Адрес длиной 32 бита. Пример: 192.0.2.25 — четыре десятичных числа от 0 до 255.

IPv6

Адрес длиной 128 бит. Пример: 2001:db8::25 — шестнадцатеричная запись с двоеточиями.

Частный IPv4

Пример: 192.168.1.20. Обычно применяется внутри локальной сети и не маршрутизируется напрямую в публичном Интернете.

Не путайте адреса: IP-адрес нужен для доставки пакетов между IP-сетями; MAC-адрес применяется для передачи кадров в пределах канального сегмента сети; доменное имя — удобное человеку символьное имя ресурса.

6. Система доменных имён DNS

DNS (Domain Name System) — распределённая иерархическая система, которая позволяет получать сведения о доменном имени. В частности, DNS может сопоставлять имя с IPv4-адресом (запись A) или IPv6-адресом (запись AAAA).

Пример обращения к веб-ресурсу

Пользователь вводит в браузере учебный адрес https://portal.example.org/lesson.

  1. Браузер определяет доменное имя portal.example.org.
  2. Через DNS-резолвер выясняется IP-адрес нужного узла (если сведения отсутствуют в кэше).
  3. Устанавливается сетевое соединение с выбранным адресом.
  4. Браузер отправляет запрос по HTTPS и получает ответ веб-сервера.

Адрес и домен приведены только как учебный пример; они не обозначают реальный школьный сайт.

Иерархия доменов читается справа налево: в portal.example.org org — домен верхнего уровня, example — домен следующего уровня, portal — поддомен.

Важно: доменное имя и IP-адрес не всегда соответствуют друг другу однозначно: одно имя может иметь несколько IP-адресов, а один IP-адрес может обслуживать несколько доменных имён.
