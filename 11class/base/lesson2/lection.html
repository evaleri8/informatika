Веб-сайт. Веб-страница. Взаимодействие браузера с веб-сервером. Динамические страницы. Разработка интернет-приложений (сайтов). Сетевое хранение данных

Как устроены веб-ресурсы и где хранятся общие файлы

Лекция Практика Домашнее задание
Цель урока: научиться различать сайт и страницу, объяснять обмен данными между браузером и сервером, понимать назначение динамических страниц и выбирать способ сетевого хранения файлов.

1. Веб-страница, веб-сайт и WWW

Веб-страница — документ, который браузер отображает как текст, изображения, ссылки и другие элементы. Основу обычной веб-страницы составляет HTML-документ. Для оформления и работы страницы могут загружаться дополнительные файлы.

Веб-сайт — связанная совокупность веб-страниц и ресурсов с общей организацией и навигацией, обычно доступная под одним доменным именем. Например, сайт школьной библиотеки может включать главную страницу, каталог и страницу контактов. Небольшой сайт может состоять и из одной страницы.

Гиперссылка позволяет перейти на другую страницу, к файлу или к нужному месту документа. WWW (Всемирная паутина) — система связанных веб-ресурсов, доступных через Интернет. Интернет обеспечивает передачу данных; WWW — один из способов его использования.

Вспомним урок 1: доменное имя обозначает сетевой ресурс, DNS помогает найти его IP-адрес, а URL задаёт адрес конкретного ресурса. Например, в https://library.example.org/catalog.html схема — https, доменное имя — library.example.org, путь — /catalog.html. Это учебный адрес; открывать его не нужно.

2. Как браузер взаимодействует с веб-сервером

Браузер — программа-клиент: она запрашивает ресурсы, обрабатывает HTML и CSS, выполняет клиентские сценарии и отображает результат. Поисковая система — отдельный интернет-сервис, которым можно пользоваться через браузер.

Веб-сервер — программа, принимающая веб-запросы и отправляющая ответы. Так также называют компьютер, на котором работает эта программа. Сервер может выдать готовый файл или обратиться к приложению, которое сформирует ответ.

Пример: открытие каталога библиотеки

  1. Пользователь вводит URL; браузер выделяет доменное имя. Если нужного адреса нет в кэше, выполняется обращение к DNS.
  2. Браузер устанавливает соединение с сервером. При HTTPS соединение защищается с помощью TLS.
  3. Браузер отправляет HTTP-запрос к ресурсу, например /catalog.html.
  4. Сервер возвращает HTTP-ответ: код состояния, служебные заголовки и, как правило, содержимое ресурса.
  5. Браузер обрабатывает HTML. Если нужны таблица стилей, изображения или сценарии, запрашивает их отдельно и отображает страницу.
Код ответаКак понимать
200 OKЗапрос успешно обработан.
404 Not FoundЗапрошенный ресурс не найден. Это не обязательно означает, что весь сервер недоступен.
Важно: HTTPS защищает данные при передаче и позволяет проверить сертификат сервера, но сам по себе не доказывает достоверность опубликованных сведений.

3. Статические и динамические страницы

Статическая страница хранится на сервере как готовый документ. Чтобы изменить опубликованный текст, автор изменяет файл и размещает новую версию. Пример — страница с историей школы.

Динамическая страница формируется или обновляется программно: её содержимое может зависеть от запроса, действий пользователя и данных. Например, каталог показывает книги по введённому автору, а личный кабинет — сведения вошедшего пользователя.

ПризнакСтатическая страницаДинамическая страница
Получение содержимогоСервер выдаёт готовый HTML-файл.Программа формирует HTML или передаёт данные для обновления страницы.
ПримерСтраница контактов школьной библиотеки.Результаты поиска по каталогу.
ОбновлениеАвтор редактирует и публикует файл.Программа обрабатывает запрос и использует актуальные данные.

Динамическая обработка может выполняться на сервере, в браузере или на обеих сторонах. Например, сервер выбирает книги из базы данных, а сценарий в браузере показывает результаты без полной перезагрузки страницы.

Не путайте: анимация или смена цвета кнопки сами по себе не означают, что сервер формирует динамическую страницу. Статический сайт тоже может содержать JavaScript. Один сайт может объединять готовые страницы и динамические разделы.

4. Из чего создают сайты и веб-приложения

HTML

Структура и смысл содержимого: заголовки, абзацы, списки, ссылки.

CSS

Оформление: цвета, размеры, расположение блоков, адаптация к экрану.

JavaScript

Программное поведение в браузере: обработка действий и обновление элементов.

Веб-приложение — программа, с которой пользователь взаимодействует через веб-интерфейс. Например, электронный дневник позволяет просматривать оценки, а онлайн-редактор — изменять документ. Серверная часть может проверять права доступа, выполнять вычисления и работать с базой данных. Для простого статического сайта она не обязательна.

Сайт можно создать вручную в редакторе кода, в конструкторе или с помощью системы управления содержимым (CMS). Даже при использовании готового средства нужно продумать структуру и проверить результат.

Основные этапы разработки

  1. Цель и аудитория. Для кого нужен сайт и какую задачу он решает?
  2. Структура и материалы. Какие страницы, тексты, изображения и переходы потребуются?
  3. Макет и оформление. Как расположить информацию, чтобы её было удобно читать?
  4. Создание. Подготовить страницы, стили и при необходимости программную часть.
  5. Проверка. Проверить ссылки, отображение на разных экранах, читаемость и работу функций.
  6. Размещение и сопровождение. Загрузить сайт на сервер, организовать доступ, обновлять материалы и сохранять резервные копии.

Хостинг — предоставление ресурсов для размещения сайта и обеспечения его доступности. Доменное имя — адресное имя, а хостинг — место и условия размещения; это разные понятия.

HTML-файл можно открыть прямо с компьютера. В этом случае браузер читает локальный файл по адресу file:///…, а не получает его по HTTP от удалённого сервера. Для знакомства с разметкой публикация в Интернете не требуется.

5. Сетевое хранение данных

Сетевое хранение — размещение файлов на устройстве или сервере, к которому обращаются по сети. Данные могут храниться в общей папке школьного сервера, на сетевом накопителе (NAS) или в облачном хранилище. Интернет нужен не всегда: школьный файловый сервер может работать только в локальной сети.

ВариантПример использованияЧто учитывать
Общая сетевая папкаУчитель размещает материалы на школьном сервере.Доступность школьной сети и выданные права.
Облачное хранилищеГруппа работает с файлами проекта с разных устройств.Учётную запись, связь, настройки доступа и наличие локальных копий.

Загрузка на сервер — передача файла со своего устройства в сетевое хранилище. Скачивание — получение файла на своё устройство. Синхронизация согласует изменения между связанными копиями файлов; её поведение зависит от настроек сервиса.

Пример: папка школьного проекта

  • Участникам, которые изменяют материалы, выдают право редактирования.
  • Тем, кто только знакомится с результатом, достаточно просмотра.
  • Если предусмотрено комментирование, рецензенту можно разрешить комментарии без изменения основного текста.
  • Доступ ограничивают нужными пользователями; перед передачей ссылки проверяют, кто сможет открыть файлы.
Синхронизация не заменяет резервное копирование: случайное удаление может распространиться на связанные устройства. Для восстановления нужна независимая копия или доступная история версий; возможности восстановления следует проверять заранее.
