ЕГЭ №26. Журнал событий и ограниченный буфер

ТеорияПрактикаДомашнее задание
Перед уроком: 10, 11, 13, 25, 27. Номера без пометки ЕГЭ относятся к первой части курса.

Что нужно понять

Высокий номер не задаёт один универсальный алгоритм. В демонстрационном варианте 2027 моделируется журнал запросов: требуется накапливать объём по клиентам и фиксировать резервные копии при нехватке места.

Сначала определите порядок запросов. Если условие не гарантирует хронологическую сортировку, сортируйте по времени с учётом правила равных времён. Перед запросом, не помещающимся в буфер, сохраняется прежний объём; затем буфер очищается и запрос добавляется.

Резервная копия получает время вызвавшего её запроса. Равенство суммарного объёма вместимости ещё не вызывает копирование. В конце нельзя создавать дополнительную копию без такого правила в условии.

Разобранный пример

Ёмкость 10. Запросы (время, клиент, объём) уже упорядочены. Найдём наиболее активного клиента и сумму двух крупнейших копий до полудня.

events=[("08:00:00",1,4),("09:00:00",2,6),("10:00:00",1,7),("11:00:00",2,5),("13:00:00",3,8)]
capacity=10
used=0
totals={}
backups=[]
for time,client,size in events:
    totals[client]=totals.get(client,0)+size
    if used+size>capacity:
        if time<="11:59:59": backups.append(used)
        used=0
    used+=size
best_client=min(totals,key=lambda c:(-totals[c],c))
print(best_client,sum(sorted(backups,reverse=True)[:2]))

Вывод программы

1 17

Копии до полудня создаются перед запросами в 10:00 и 11:00. Текстовое сравнение времени корректно для фиксированного формата ЧЧ:ММ:СС с ведущими нулями. В примере равенство сумм клиентов разрешается меньшим ID; реальное условие может гарантировать единственность.

На что обратить внимание

Если требуется ровно две копии, проверьте наличие двух. Учебные файлы их гарантируют. Выбор двух наибольших значений можно сделать за один проход без хранения всех копий.
