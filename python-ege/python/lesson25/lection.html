Что нужно понять

Модель хранит только существенное состояние: позицию головки, содержимое ленты, состояние автомата; либо занятый объём и текущий запрос. Один шаг должен точно соответствовать одному правилу задачи.

Машину Тьюринга удобно задавать словарём переходов (состояние, символ) → (новый символ, движение, новое состояние). Ленту можно хранить словарём с пустым символом по умолчанию, включая отрицательные позиции.

События обрабатывают в заданном порядке. Проверка переполнения до добавления запроса и после него описывает разные модели. Граница «не больше» включает равенство.

Разобранный пример

Смоделируем буфер ёмкости 10: перед запросом, который не помещается, накопленные данные сохраняются и буфер очищается.

capacity = 10
requests = [4, 6, 3, 8, 2]
used = 0
backups = []
for size in requests:
    if used + size > capacity:
        backups.append(used)
        used = 0
    used += size
print(backups)
print(used)

Вывод программы

[10, 3]
10

Запрос 6 помещается к уже накопленным 4, поскольку 4+6=10. Сохранение происходит перед следующим запросом. Оставшиеся данные в конце не добавляются в backups: завершающее сохранение условием не предусмотрено.

На что обратить внимание

Нельзя добавлять неописанное финальное событие. Ограничение числа шагов симуляции — защита от ошибки, но достижение ограничения не является ответом задачи.
